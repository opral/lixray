Home file explorer — folder navigation

Feedback being addressed: entering a folder shifts the whole layout (the 1020px grid with the right rail collapses to a 760px single column) and there is no obvious way back to the root.

Every variant below is clickable — enter folders, go back up. Watch what the header does.

Fixed premise (your proposal 1): all variants keep the root layout when navigating into folders — same grid, same rail, same width. The rail stays repository-scoped (About / Changes / Database don't change per folder). The variants only differ in the header affordance (decision 2) and where Connect agent / Invite live (decision 3).

2a + 3aBreadcrumb in the header, agent & team actions in the railRECOMMENDED

The "FILES" label is replaced by a breadcrumb that always starts at the repository name — at root it reads like a title, in folders each ancestor is clickable. Connect agent and Invite move to a new "Team & agents" rail section, so the header only carries navigation + New and never wraps. Trade-offs: + matches the top-bar breadcrumb pattern we just shipped (dev / peter); + scales to deep paths (middle segments collapse to “…”); − repo name appears twice on screen (top bar and here).

2b + 3aBack arrow + current folder name

Finder-style: a single ← button (disabled at root) plus the current folder name; the header otherwise never changes. Actions also moved to the rail. Trade-offs: + minimal, zero layout churn; + the ← position is a stable click target for walking all the way up; − no random-access to ancestors (must click ← repeatedly); − “where am I?” only shows one level.

2c + 3aPersistent “FILES” label + “..” up-row in the list

The header literally never changes ("FILES" + New). Navigation state lives in the list itself: a subdued .. (up) row pinned first inside folders, and a small path line under the label. Trade-offs: + absolutely zero header movement; + the up-affordance is where the eyes already are (the list); − ".." is developer-culture, less obvious to non-technical teammates; − path line is small.

2a + 3bBreadcrumb, but actions stay in the header (for comparison)

Same breadcrumb as A but Connect agent / Invite stay where they are today. Trade-offs: + agent CTA stays prominent on the primary surface; − on deep paths the header wraps to two lines (resize this window to see) — exactly the kind of shift we're trying to kill; − crowded.
